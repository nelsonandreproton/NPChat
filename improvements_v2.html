🔄 Ollama → LM Studio Migration

Why this migration is clean

LM Studio exposes an OpenAI-compatible REST API at http://localhost:1234/v1. Your codebase uses ollama.Client directly in 5 files — but all calls map 1:1 to OpenAI SDK equivalents. The migration is a library swap (ollama → openai) plus a URL change. No architectural changes needed. All RAG logic, ChromaDB, BM25, caching, and feedback remain identical.

⚪ Ollama (current)
🔌Separate background service, runs at port 11434
📦Models managed via ollama pull CLI
🖥️No GUI — terminal only
📐Custom Python SDK (ollama package)
🔧Health check via ollama.Client.list()
⚡Model switching requires CLI commands
📊No built-in token/performance stats UI
🟣 LM Studio (target)
🔌Local server at port 1234, OpenAI-compatible
📦Models managed via GUI — search, download, switch
🖥️Full desktop GUI with chat, model browser, settings
📐Standard openai Python SDK — industry standard
🔧Health check via GET /v1/models
⚡Model switching in GUI — hot swap without restart
📊Built-in token stats, TTFT, speed (tok/s) in GUI

Core API Call Translation

# ── GENERATION (llm.py) ──────────────────────────────────── - response = client.chat(model=config.llm_model, - messages=[{"role": "system", "content": system}, - {"role": "user", "content": user}]) - return response["message"]["content"] + response = client.chat.completions.create( + model=config.llm_model, + messages=[{"role": "system", "content": system}, + {"role": "user", "content": user}]) + return response.choices[0].message.content # ── EMBEDDINGS (embedder.py) ──────────────────────────────── - resp = client.embeddings(model=config.embedding_model, prompt=text) - return resp["embedding"] + resp = client.embeddings.create(model=config.embedding_model, input=text) + return resp.data[0].embedding # ── HEALTH CHECK (routes.py) ──────────────────────────────── - ollama.Client(host=config.ollama_base_url).list() + client.models.list() # GET /v1/models — works with LM Studio
