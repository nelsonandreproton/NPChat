1. Visão Geral do Sistema

O NPChat é um chatbot RAG (Retrieval-Augmented Generation) que responde perguntas sobre a Near Partner usando conteúdo raspado do site oficial. Funciona 100% local via Ollama — sem chaves de API externas.

nearpartner.com blog + páginas
→
Scraper BeautifulSoup
→
JSON blog_posts / company_pages
→
Ingestão chunk + embed
→
ChromaDB vector store
Utilizador pergunta (PT / EN)
→
FastAPI / Streamlit rate limit + sanitize
→
RAG Chain expand → retrieve → generate
→
Ollama LLM gemma2:2b
→
Resposta + fontes + log

Interfaces

  • Streamlit (4 tabs: Chat, Analytics, ChromaDB, Settings)
  • FastAPI REST API (/api/v1/chat, /feedback, /health)
  • Streaming SSE (/chat/stream)

Fontes de Conhecimento

  • Blog posts scrape incremental
  • 13 páginas de empresa
  • Chunks de ~1200 chars (~300–400 tokens)
  • Sobreposição de 200 chars

Persistência

  • ChromaDB — embeddings
  • query_logs.db — analytics
  • response_cache.db — cache LLM
  • feedback.db — feedback bruto
  • feedback_learning.db — aprendizagem

2. Pipeline RAG — Pergunta → Resposta

Cada pergunta passa por até 5 fases dentro de EnhancedRAGChain.

1

Sanitização do Input

Truncagem a 1000 chars, remoção de null bytes, strip. Protecção contra prompt injection.

src/generation/prompts.py · sanitize_user_input()
2

Query Expansion (opcional)

O LLM expande a pergunta com sinónimos e reformulações. Aumenta o recall. Alternativa: HyDE — gera resposta hipotética e embeda-a em vez da pergunta.

src/retrieval/query_expansion.py · QueryExpander.expand_query() / generate_hyde()
3

Retrieval Híbrido (Semântico + BM25)

Busca em dois vectores em paralelo e combina com Reciprocal Rank Fusion (RRF). Pesos: 70% semântico + 30% BM25. O FeedbackLearner ajusta scores com base no historial.

src/retrieval/hybrid_retriever.py · HybridRetriever.retrieve()
4

Construção do Prompt

Combina contexto recuperado + histórico de conversa (últimas 3 trocas) + pergunta. System prompt em português, inclui valores e serviços da Near Partner.

src/generation/prompts.py · build_rag_prompt()
5

Geração LLM (Ollama)

Modelo local gemma2:2b (configurável: mistral:7b, etc.). Opcionalmente auto-avalia a confiança da resposta (0.0–1.0) numa segunda chamada LLM.

src/generation/llm.py · OllamaLLM.generate()
6

Cache + Log + Resposta

Resultado guardado no ResponseCache (SQLite, TTL 24h). Query registada no QueryLogger com scores e tempo de resposta. Devolvidos: resposta, fontes, log_id, chunk_ids.

src/analytics/response_cache.py · src/analytics/query_logger.py

3. Ingestão de Conhecimento

3a. Scrapers

scraper.py — Blog Posts

  • Percorre blog.nearpartner.com página a página
  • Extrai URLs com padrão /YYYY/MM/post/
  • Scrape incremental (só posts novos)
  • Extrai: título, autor, categorias, data, conteúdo limpo
  • Remove sidebar, metadados de fim, "LATEST POST"
  • Output: nearpartner_blog_posts.json

scrape_company_pages.py — Páginas da Empresa

  • 13 páginas fixas (homepage, serviços, sobre, etc.)
  • Mesmo pipeline de limpeza de conteúdo
  • Output: nearpartner_company_pages.json
  • Delay 2.2s entre pedidos (polite scraping)
  • User-Agent identificado como scraper interno

3b. Pipeline de Ingestão

JSON files blog + company
→
TextChunker ~1200 chars, overlap 200
→
Embedder nomic-embed-text
→
VectorStore ChromaDB add_chunks()
→
nearpartner_knowledge colecção ChromaDB

3c. Estratégia de Chunking

Split por parágrafos duplos (\n\n)
Preserva fronteiras semânticas naturais do texto
Headings agregados ao parágrafo seguinte
Título <100 chars sem pontuação final → prefixado ao conteúdo
Agrupamento em chunks de ~1200 chars com overlap de 200
Último parágrafo do chunk anterior reutilizado como contexto no seguinte

4. Retrieval Híbrido — Semântico + BM25

Busca Semântica (70%)

Query → nomic-embed-text vector 768 dims via Ollama
↓
ChromaDB similarity search L2 distance → similarity score = 1/(1+dist)
↓
Top K×2 resultados para fusão RRF

Busca BM25 (30%)

Índice BM25Okapi construído on-demand a partir de todos os docs ChromaDB
↓
Tokenização lowercase + regex \b\w+\b query expandida se disponível
↓
Top K×2 resultados com score > 0 para fusão RRF

Reciprocal Rank Fusion (RRF)

Fórmula: RRF_score = Σ weight / (k + rank)

  • k = 60 (constante padrão RRF)
  • Semântico: 0.7 / (60 + rank + 1)
  • BM25: 0.3 / (60 + rank + 1)
  • Documentos que aparecem em ambas as listas recebem score combinado
  • Resultado final ordenado por RRF score descendente
  • Índice BM25 reconstruído automaticamente quando ChromaDB muda

Query Expansion + HyDE

Expansion (padrão)

  • LLM gera versão expandida com sinónimos e reformulações
  • Expansão concatenada à query original
  • Skipped para queries <= 2 palavras (saudações)
  • Temperature 0.3, max 150 tokens

HyDE (Hypothetical Document Embedding)

  • LLM gera resposta hipotética de 50–100 palavras
  • Essa resposta é embedada em vez da pergunta
  • Encontra documentos semelhantes à resposta esperada
  • Útil para perguntas abstractas ou conceituais

5. Sistema de Feedback e Aprendizagem Automática

Cada resposta inclui botões 👍/👎. O FeedbackLearner processa o feedback em tempo real e aplica 4 tipos de acções automáticas.

Feedback Acção 1 — Cache Acção 2 — Chunks Acção 3 — Flagging Acção 4 — Mapeamento
👍 Positivo Cache mantido +0.10 boost em todos os chunk_ids usados — Query + chunk_ids guardados em query_mappings
👎 Negativo Invalidar entrada de cache para esta query -0.15 penalização em todos os chunk_ids usados Contagem de negativos. Se ≥ 2 → flag "pending" —

Fluxo de Ajuste de Scores no Retrieval

Resultados HybridRetriever combined_score (RRF)
→
FeedbackLearner apply_adjustments_to_results()
→
adjusted_score = combined_score ± adjustment
→
Re-sort por adjusted_score clamp [0, 1]

Tabela chunk_adjustments

feedback_learning.db

  • chunk_id (TEXT UNIQUE) → identificador do chunk
  • score_adjustment (REAL) → acumulado ao longo do tempo
  • positive_count / negative_count — rastreabilidade
  • Scores boostados em futuras buscas para o mesmo chunk

7. API REST (FastAPI)

Servidor em 127.0.0.1:8000 (localhost only). Rate limit: 30 requests/min por IP (sliding window in-memory). CORS permitido apenas para localhost:8501 (Streamlit).

Endpoints

POST
/api/v1/chat
Pergunta ao chatbot. Suporta conversation_history (multi-turn), top_k, temperature. Verifica cache primeiro.
POST
/api/v1/chat/stream
Resposta em streaming via Server-Sent Events (SSE).
POST
/api/v1/feedback
Submete feedback (thumbs_up/down) + chunk_ids. Dispara FeedbackLearner.process_feedback().
GET
/api/v1/sources
Lista todas as fontes únicas na knowledge base (URLs + metadados).
GET
/api/v1/health
Estado do serviço: Ollama conectado? Vector store count? Status healthy/degraded.

Inicialização Lazy dos Componentes

EnhancedRAGChain

  • Criado na 1ª chamada /chat
  • Singleton por processo

VectorStore

  • Singleton lazy
  • Partilhado com /sources

ResponseCache

  • Singleton lazy
  • SQLite thread-safe

FeedbackLearner

  • Singleton lazy
  • Processamento sync

8. Agendamento Automático (APScheduler)

Arranca em background quando o Streamlit inicia. Mantém o conhecimento actualizado automaticamente.

Mon 02:00
Full Update
scraper.py → scrape_company_pages.py → scripts/ingest_blogs.py
Daily 03:00
Cache Cleanup
ResponseCache.clear_expired() — remove entradas com > 24h
Sun 23:00
Weekly Report
Gera relatório em data/reports/weekly_YYYYMMDD.txt com estatísticas, gaps de conhecimento e queries flagged

Conteúdo do Relatório Semanal

data/reports/weekly_YYYYMMDD.txt

  • Total de queries na semana
  • Score médio de retrieval
  • Contagem de feedback positivo/negativo
  • Chunks ajustados pelo sistema de aprendizagem
  • Top 10 queries com baixo score (gaps de conhecimento)
  • Queries flagged pendentes de revisão humana
